| Term / Термин | Meaning / Значение |
|---|---|
| Artifact | A file or package produced by the build process. / Файл или пакет, създаден от процеса по build. |
| CI | Continuous integration: every change is built and tested automatically. / Всяка промяна се изгражда и тества автоматично. |
| Container | An isolated environment used to run an application and its dependencies. / Изолирана среда за стартиране на приложение и зависимостите му. |
| Deployment | Putting a version of the service where users can reach it. / Поставяне на версия на услугата там, където потребителите я достигат. |
| Health check | An endpoint that says whether the service is alive. / Адрес, който показва дали услугата работи. |
| Issue | A task, bug or idea tracked on GitHub. / Задача, бъг или идея, проследявани в GitHub. |
| Pipeline | An automated sequence of build, test and deployment steps. / Автоматизирана последователност от build, test и deployment стъпки. |
| Pull request | A proposal to merge one branch into another, with review. / Предложение един клон да се слее в друг, с ревю. |
| Rollback | Returning to a previous working version. / Връщане към предишна работеща версия. |
| Tag | A named reference to a specific commit, often used for releases. / Именувана референция към конкретен commit, често използвана за release. |
| Version | A named state of the service, e.g. 0.2.0. / Именувано състояние на услугата, напр. 0.2.0. |
